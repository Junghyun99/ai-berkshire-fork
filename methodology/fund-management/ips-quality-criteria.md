# Phase 1-2 — IPS 품질 평가 루브릭 및 출고 게이트

- 작성일: 2026-10-28
- 성격: **방법론 초안**. 평가 규칙은 아직 코드로 구현되지 않았고 실제 사용자 정책에도 적용되지 않았다.
- 참조: `research/phase1-1-investment-policy-methodology.md`, `methodology/fund-management/architecture.md`.
- 산출물: [investment-policy-template.md](investment-policy-template.md)

## 1. 평가 목적 및 대상

투자정책은 멋진 서술이 아니라 **장기간 반복되는 투자 의사결정의 상위 계약**이다. 따라서 좋은 정책은 (a) 투자자 목표와 제약을 드러내고, (b) 서로 모순되지 않으며, (c) 측정·집행 가능하고, (d) 승인·변경 이력이 보존되어야 한다.

검토 단위는 `InvestmentPolicy`의 **불변 버전**. 스킬의 투자 제안을 평가할 때 반드시 그 시점의 승인된 버전에 연결한다.

## 2. 다섯 가지 평가 차원

| 차원 | 체크 항목 | 대표적인 결함 |
| --- | --- | --- |
| **완전성** | 운용 범위, 목적, 수익/위험 목표, 기간, 현금흐름, 자산범위, 한도, 배분, 벤치마크, 승인/변경 체계가 있는가? | 손실 감당 능력 없이 MDD만 규정 |
| **일관성** | 목표수익과 위험 예산·유동성 요구가 양립하는가? 허용 자산군과 금지 목록이 충돌하지 않는가? | 6개월 내 인출 자금에 비유동 자산 100% |
| **실행 가능성** | 누가 어떤 데이터를 이용해 한도와 조정 규칙을 수행하는가? 필요한 데이터가 이용 가능한가? | 계산 근거 없는 '과열 시 적절히 축소' |
| **검증 가능성** | 지표의 계산·기준시점·통화·분모·예외/판정이 정의되어 기계적으로 검사할 수 있는가? | '최대 비중 10%'의 분모 불명 |
| **재현성/거버넌스** | 정책 버전, 승인자, 유효기간, 근거, 당시 포트폴리오 스냅샷을 연결할 수 있는가? | 정책을 덮어써 과거 결정의 적법성 확인 불가 |

## 3. 0–3 등급 척도 (품질 진단용, 승인 점수 아님)

| 점수 | 기준 |
| ---: | --- |
| 0 | 관련 내용 없음 또는 상충되는 근거 |
| 1 | 원칙만 있고 정의·데이터·책임자 부족 |
| 2 | 필요한 정의는 대부분 있으나 일부 경계조건/검증 근거 미정 |
| 3 | 담당자·범위·정의·검증·예외 및 기록을 포함해 실제 평가 가능 |

- 합계 15점은 **품질 개선 우선순위**를 위한 보조지표이지 투자 가능성을 보증하지 않는다.
- 점수가 높더라도 **필수 차단 조건 하나라도 있으면 활성화 금지**.
- 정성적 일관성(목표수익의 실현 가능성)은 불확실성·가정과 보수/기준/낙관 시나리오를 함께 기록하고 단순 pass로 처리하지 않는다.

## 4. Hard Gate: ACTIVE 전환 차단 조건

아래 중 하나라도 해당하면 **NOT_READY**로 판정한다.

| 게이트 | 차단 조건 |
| --- | --- |
| G01 Ownership | owner, policy_id, 대상 포트폴리오, 승인자 불명 |
| G02 Scope | 적용 계좌/자산 범위 또는 기준통화 없음 |
| G03 Objective | 투자 목적/기간/예상 인출 의무 미정 |
| G04 Risk | 감수 능력/의향을 구분하지 않았거나 정량적 강행 한도·계산 기준 불명 |
| G05 Universe | 허용/금지 자산 충돌, 레버리지·파생 허용 여부 불명 |
| G06 Allocation | SAA 목표 합계 ≠100% 또는 밴드 하한>목표·목표>상한 |
| G07 Basis | 종목/산업 한도의 분모(전체 포트폴리오 등), 통화·기준일 없음 |
| G08 Benchmark | 벤치마크나 평가 대상·기간이 불명(명시적 예외에는 사유·승인 필요) |
| G09 Governance | 승인·변경·유효시점/만료 규칙 없음 |
| G10 Provenance | 정책 버전, 출처, 승인·개정 이력 연결 불가 |
| G11 Validation | 컴퓨터 검사에 필요한 가격/환율/보유정보를 확보할 수 없음 |
| G12 Feasibility | 목적·위험·현금흐름 사이의 중대한 충돌이 해소되지 않음 |

**주요 정책 경계:** 아직 Phase 2의 SAA 수치가 정해지지 않았다면 문서는 계속 DRAFT/REVIEW로 둘 수 있고, 리서치용으로 활용할 수 있다. ACTIVE 전환에는 본 설계에서 정한 SAA 필수값을 채워야 한다. 향후 '리서치 전용 정책'을 별도 허용하려면 명시적 policy_type과 축소된 게이트를 **추가 설계**해야 한다. 자동으로 예외를 만들지 않는다.

## 5. Soft Guideline과 Hard Limit 분리

- **Hard limit:** 정량적 집중도, 투자 금지 범위, 레버리지 한도, 유동성 하한, 사용자 승인. 위반 시 `FAIL` 또는 `UNKNOWN`으로 승인 차단.
- **Soft guideline:** 투자 철학, 선호 산업, 장기 보유 원칙. 위반은 이유와 대안 제시를 요구하되 강행 한도 위반을 치유하지 못한다.
- **미확정 정책 값:** `TBD` 그대로 유지. 대화형 AI가 추천한 숫자를 사용자 승인 없이 활성 값으로 사용하지 않는다.

## 6. 품질 평가 출력 계약(예시)

```json
{
  "policy_id": "example",
  "version": "0.1-draft",
  "evaluated_at": "2026-10-28",
  "dimension_scores": {
    "completeness": 1,
    "consistency": 1,
    "operability": 0,
    "testability": 0,
    "traceability": 2
  },
  "gate_failures": ["G04", "G06", "G09"],
  "decision": "NOT_READY",
  "unresolved_items": [
    {
      "field": "risk_limits.single_name",
      "problem": "종목 최대 비중 및 분모 미정",
      "needed_from": "policy_owner"
    }
  ]
}
```

모든 값은 **진단 형식 예시**이지 이 프로젝트 정책을 평가한 결과가 아니다.

## 7. 충돌·누락을 찾아내는 평가 질문

| 질문 | 해당 차원 | 기대 대응 |
| --- | --- | --- |
| 기대수익률을 높게 잡았는데 손실·레버리지 한도는 낮은가? | 일관성 | 전제가 성립하는지 시나리오 검토, 목표/한도 재협의 |
| 투자기간은 장기지만 단기 큰 인출이 있는가? | 일관성/완전성 | 현금흐름·유동성 버킷 분리 |
| 현금 10% 제한과 1년 내 인출 준비금이 충돌하는가? | 일관성 | 제한의 분모와 우선순위 명시 |
| `position_plan.py`가 10%, IPS가 5%라고 하면? | 검증 가능성 | 상위 IPS 5%가 우선 |
| 동일 종목이 여러 계좌에 있는가? | 실행 가능성 | 중복 합산/통화 변환 규칙 요구 |
| 과거 투자 심의의 근거 정책이 사라졌는가? | 재현성 | 새 정책은 신규 버전, 과거 것은 불변 유지 |
| 유동성·레버리지 한도가 숫자는 있으나 데이터가 없는가? | 검증 가능성 | `UNKNOWN`; 투자 제안 승인 차단 |

## 8. 검토 절차

```text
IPS DRAFT
   ↓ 문서/필드 수집
Quality Review (5차원 0–3점 + G01–G12)
   ├─ 결함 → REVISION_REQUIRED
   └─ 검토 통과 → POLICY_OWNER_REVIEW
                            ├─ 반려/보완
                            └─ 명시적 승인 → ACTIVE_VERSION
                                                  ↓
                                           이후 변경은 신규 버전
```

승인은 **사람의 행위**로만 수행한다. 평가 점수만으로 승인하지 않는다.

## 9. 향후 테스트 목록

| ID | 입력 | 기대 |
| --- | --- | --- |
| Q01 | IPS 미승인 | 투자 제안 승인 불가 |
| Q02 | 자산별 목표 40%+40%=80% | G06 실패 |
| Q03 | 종목 한도만 있고 분모 없음 | G07 실패 |
| Q04 | risk capacity 누락 | G04 실패 |
| Q05 | 허용 자산에 금지 자산 포함 | G05 실패 |
| Q06 | 승인 없는 정책 한도 수정 | 활성 버전 불변 |
| Q07 | 6개월 내 지급의무 vs 비유동 비중 과다 | G12 검토 실패 |
| Q08 | 코드가 검증할 데이터 소스 없음 | G11 실패 |
| Q09 | 15/15점이나 G01 소유자 누락 | NOT_READY |
| Q10 | 변경 전 투자 기록 조회 | 당시 유효한 policy_version 반환 |

이 테스트는 **향후 자동화를 위한 수용 기준**이며, 현재 구현·실행한 것은 아니다.

## 10. Phase 1-3 인계

Phase 1-3에서는 이 템플릿과 루브릭을 사용해 **정책 작성 → 검토 → 수정 → 사용자 승인 → 불변 버전 발행 → 갱신** 흐름을 설계한다. 아직 개인의 실제 투자 목표·위험 한도를 채우거나 활성 정책을 만들지 않는다.

권장 인계 산출물:
- 승인·개정 상태 전이 표 및 감사 로그 형식
- 작성 인터뷰 질문지와 누락 정보 처리
- 기존 운용보고서/판단 원장 연결 지점
- `G01–G12` 결정론적 검사와 정성 심사 분리 계획

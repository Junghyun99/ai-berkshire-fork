# 기존 Skill 재사용과 연구 산출물 연결 범위

2026-11-22 · 설계/코드 대조 결과 · 런타임 통합 검증 아님

## 현재 연구 위치

자산배분 탐색의 잠정 결론 이후, Phase 3 의사결정 연구에서 기존 산출물을 정책·자산배분 검토에 연결하는 범위를 정리한다. 기업·산업 분석과 종목 판단은 기존 Skill을 재사용한다. 새 기업 분석 Skill, 두 번째 종목 판단기, 별도 판단 원장을 만들지 않는다. Phase 2 전체 완료나 최종 SAA 확정을 의미하지 않는다.

## 원래 판단을 유지하는 규칙

investment-team은 05 토론 결과를 §7 최종 판단에 연결하며 관점별 의견을 다수결로 합산하지 않는다.

| 토론 판정 | 기존 최종 의견 |
| --- | --- |
| 강세 우세 | 매수 |
| 균형 | 관망 |
| 약세 우세(가격) | 관망 |
| 약세 우세(영구 손실) | 회피 |

후속 연결 단계는 이 판단을 다시 투표하거나 덮어쓰지 않는다. 새 증거가 원 판단을 바꿀 경우 기존 분석·판단 단계로 돌아가 변경 이유와 버전을 남긴다. 실행계획 단계가 독립적으로 원 판단을 바꾸지 않는 기존 규칙도 유지한다.

## 구분해야 할 세 가지 상태

1. **종목 연구 의견:** 기존 Skill의 매수/관망/회피.
2. **후속 검토 전달 상태:** 전달 가능/보완 필요/해당 없음. 이 표현은 설계용 어휘이며 구현된 CLI enum이 아니다.
3. **투자 제안 승인:** 정책 검증 및 사용자의 별도 승인. 현재 IPS DRAFT는 연구 의견으로 활성화되지 않는다.

예를 들어 매수 의견이 있어도 제안 비중의 분모가 없으면 원 의견을 보존하고 비중 제안 전달에 필요한 보완을 요청한다. 자료가 완전한 관망 의견을 매수로 승격하지 않는다. 기존 v0.1 카드의 채택·보류·기각을 별도 종목 판단 체계로 구현하지 않는다.

## 최소 연결 정보

| 정보 | 기록·확인 내용 |
| --- | --- |
| 원본 식별 | 보고서 경로, 커밋, 정확한 근거 절, 작성·판단 기준시각 |
| 검사 연결 | 같은 보고서 버전에 대한 검사 로그, 미검증 범위 |

| 비중의 의미 | 전체 포트폴리오/주식/테마 중 분모, 정책 버전, 자산배분 시나리오. 미확인은 그대로 기록 |
| 보완 책임 | 기존 어느 단계가 보완할지와 재검토 계기 |

report_check의 문구·라벨 존재 검사와 반증의 경제적 의미·관측 가능성 검토는 다르다. decision_ledger의 반증 문자열 파싱도 의미 검증을 대체하지 않는다. 이 연결 설계에 실제 계좌 잔고를 요구하지 않는다.

## 설계 수용 사례

실행한 Python 테스트나 실데이터 검증 결과가 아니라 다음 작업에서 확인할 기대 동작이다.

| 사례 | 기대 동작 |
| --- | --- |
| 매수, 비중 분모 누락 | 매수 유지, 비중 전달 보완 요청 |
| 관망, 기존 검사 통과 | 관망 유지, 논지 추적 가능; 매수로 변경하지 않음 |
| 반증 지표의 평가기간 누락 | 원 작성/추적 단계에 기간 보완 요청 |
| 테마 내부 비중만 존재 | 전체 포트폴리오 비중으로 합산하지 않음 |
| 원 보고서 수정, 검사 로그는 구버전 | 관련 검사를 새 버전에 다시 연결 |
| 매수, 정책 DRAFT | 연구 기록 가능, 투자 승인으로 승격하지 않음 |

## 다음 완료 단위

1. 기존 보고서 한 건의 원 판단·근거·반증·실행계획·검사 결과를 위 연결표에 대응한다. 새 가격 수집·가치평가를 선행조건으로 두지 않는다.
2. 기존 파서로 읽을 수 있는 항목과 사람이 의미를 검토해야 할 항목을 구분한다.
3. 반복되는 기계 판독 누락이 실제 확인될 때만 기존 도구의 호환 확장과 회귀 테스트를 제안한다.

완료 기준은 원 의견을 바꾸지 않고 후속 검토가 필요한 입력·누락·담당 단계를 식별할 수 있는가다. 기업 가치평가 완성 여부가 아니다. PR #109의 기업 리서치 초안은 독립 연구로 보존하며 이 작업의 의존 PR로 두지 않는다.

이번 변경은 문서 정정이다. 기존 Skill·Python·보고서·원장은 수정하지 않는다. Skill 실행, 새 백테스트 및 전체 Python 테스트 완료를 주장하지 않는다. 공식 자료·빈티지·미래 평가·정책 선택의 기존 미결 항목도 유지한다.

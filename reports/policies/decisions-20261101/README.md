## Phase 2-4로 넘길 구현 계약

1. 현금흐름: 계좌 밖 납입·인출과 계좌 간 내부 이전을 구분한다. 이전 두 다리를 연결하고 수수료·세금은 별도 기록한다. 날짜·통화·금액·가용일·수집 근거가 없으면 미정으로 남긴다. 개인 원본은 GitHub에 올리지 않는다.
2. 성과: TWR/MWR 정의, 입출금 시각과 평가 시각, 수익률 미정의 조건 및 환산 규칙을 설계한다. 실제 자산·현금흐름과 합성 회귀 입력을 분리한다. 현재 월별 엔진이 이 계약을 구현했다고 주장하지 않는다.
3. 계좌: 계좌유형·상품·규정 유효기간·증권사·공식 출처를 근거로 적격성을 판정한다. 근거 미확보는 UNKNOWN이며 허용으로 간주하지 않는다. 실제 계좌번호·API 키를 요구하지 않는다.
4. 레버리지: 일별 기초 TR·일일 재설정·비용·상장기간과 보유금액/기초 노출을 구분하는 계약을 먼저 만든다. 상장 전 합성 자료는 추정 시뮬레이션으로 분리한다.
5. 검증: 외부 납입·인출, 내부 이전 상쇄, 환율 시차, 누락 평가, 인출 불가, 납입 중단, 급락 중 인출, 레버리지 경로 차이를 합성 사례로 검사한다. 새로운 엔진과 테스트는 후속 PR 범위다.

## 사용자 질문 묶음 — 아직 답변을 받은 것이 아님

Phase 2-4 계약·실현 가능성 검토 후 다음 순서로 제시한다. 이번 목록 작성만으로 답변 요청이나 정책 선택이 완료된 것은 아니다.

- 1차 생활·현금흐름: 투자 외 비상자금 분리 여부, 예정 인출의 시기/범위/필수성, 정기납입의 주기/범위/중단 가능성. 먼저 범주만 받아도 되며 미정 응답을 허용한다.
- 2차 위험·구성: 손실이 필수지출에 미치는 영향, 회복기간 허용 범위, 스트레스 결과를 본 뒤 현금·집중·레버리지 한도 및 조정 원칙을 선택한다.
- 3차 평가·정책: 지표·벤치마크·RF/MAR·동결 조건을 선택하고, 별도로 최종 IPS 버전과 승인 범위를 확인한다.

숫자 응답을 받을 때 단위·기준통화·분모·주기·적용 범위를 함께 기록한다. 원문 응답, 날짜, 결정 주체, 근거, 변경 전후, 영향 문서와 PR을 연결한다. 실제 선택이 생긴 뒤 DECISIONS에 추가하고 새 IPS DRAFT를 만든다. 이번에는 DECISIONS와 IPS v0.4를 수정하지 않는다.

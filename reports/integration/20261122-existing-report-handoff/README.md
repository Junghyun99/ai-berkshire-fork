# 기존 보고서의 후속 검토 연결 사례 — MSFT

2026-11-22 · 연구 산출물 연결 검증 · 신규 기업 분석/투자 판단 아님

## 결론

기존 보고서의 관망 ★3 판단과 최종 실행계획을 기존 파서로 읽을 수 있고, 06 리스크 토론과 최종보고서의 계획도 일치한다. 그러나 조건의 AND/OR 차이, 비중 분모·정책 버전, 반증 지표의 기간 정의가 남아 **의견 기록은 전달 가능, 자동 조건 평가와 포트폴리오 비중 연결은 보완 필요**다. 이는 설계상 전달 상태이며 새 CLI 상태나 원장 의견이 아니다.

[연결 범위](../../../methodology/fund-management/skill-reuse-and-handoff.md)에 따라 원 보고서와 원장을 수정하지 않았다. 아래 가격·가치·비중은 기존 보고서의 문자열/파싱 결과이며 이번에 검증한 시장 사실 또는 새 투자 제안이 아니다. 정책은 DRAFT다.

## 확인된 보완 항목과 담당 단계

| ID | 관측한 문제 | 담당·해결 기준 |
| --- | --- | --- |
| H01 | §1/§5.5는 FCF 증가 **그리고** 가격 ≤430, §8은 FCF 증가 **또는** 가격 <430으로 읽힌다. 논리 연산자와 경계 포함 여부가 다름 | 원 최종 종합 단계가 §1/§5.5와 요약의 의도를 일치시킴. 이 사례는 어느 쪽도 새 판단으로 선택하지 않음 |
| H02 | 분기마다 확인한다는 점검 주기는 있지만, FCF 전년 대비가 단일 분기/누적/TTM/연간 중 어느 값인지 및 리스 차감 항목·결측 처리의 실행 가능한 정의가 부족 | 원 분석/논지 추적 단계에서 산식·비교기간·자료 위치·결측 처리 명시. 새 수치나 문턱 생성 금지 |
| H03 | 상한 4%의 분모(총 포트폴리오/주식/테마), 기존 보유 포함 여부와 적용 정책 버전·배분 시나리오가 명시되지 않음 | 기존 실행계획/후속 배분 검토가 의미를 보완. 기본 최대비중을 정책값으로 대입하지 않음 |
| H04 | parse_plan 결과에 가격 통화가 별도 필드로 없고 차수별 조건이 빈 문자열임. 원문에는 USD와 전체 계획의 대기 조건이 있음 | 기존 파서 결과와 원문 근거·현재상태를 함께 전달. 통화/조건 누락을 잘못된 기본값으로 보충하지 않음 |
| H05 | 원문은 과거 표본검사 15/94 통과를 기록. 이번 고정 seed 추출은 14/93이며 원문에 과거 seed·실행 도구 커밋·표본별 결과 경로가 명시되지 않음 | 기존 감사 단계가 과거 로그와 당시 보고서/도구 버전을 연결해야 재현 가능. 차이만으로 과거 감사가 잘못됐다고 단정하지 않음 |
| H06 | 데이터 날짜/출처 목록이 있으나 항목별 가용시각과 정확한 판단 cutoff 연결은 별도 확인 필요 | 기존 자료 품질/가용시점 과제로 인계. 과거 시점 백테스트 입력으로 곧바로 재사용하지 않음 |

H01은 형식 검사가 PASS여도 남는 의미 불일치의 실제 사례다. H02~H06까지 모두 자동 파서가 해결해야 한다는 뜻은 아니다. 원 작성 단계의 설명 보완과 도구 확장 필요성을 구분한다.

## 재현 방법

위 기준 커밋의 분리된 체크아웃에서 evidence.json의 command 배열을 순서대로 실행한다. 명령에는 시세 조회·원장 쓰기가 없다. 원문 파싱 비교는 다음과 같다.

```python
import sys
from pathlib import Path
sys.path.insert(0, "tools")
import decision_ledger as dl
import position_plan as pp

final = Path("reports/마이크로소프트/최종보고서.md").read_text()
risk = Path("reports/마이크로소프트/06-리스크토론-비중.md").read_text()
print(dl.parse_label(final))
print(dl.parse_run_info(final))
print(pp.parse_plan(final))
assert pp.parse_plan(final) == pp.parse_plan(risk)
```

출력 시간 등 환경 의존 값은 달라질 수 있다. 원본과 도구 해시 및 의미 있는 결과를 비교한다. 이번 사례는 입력 대응과 실제 누락 식별까지 완료했다. 다음은 다른 기존 보고서 한 건에서 H01~H04의 반복 여부를 확인해 원 작성 규칙 보완과 최소 파서 확장 중 필요한 변경을 결정하는 것이다. 새로운 판단 엔진이나 기업 가치평가 완성을 요구하지 않는다.

# 두 번째 기존 보고서 연결 점검과 최소 보완 결정

2026-11-22 · Codex/Work · 기업 재분석이 아닌 문서/파서 연결 검증

## 결론

어도비 사례에서도 비중 분모 미명시와 차수 조건의 문장 분산을 확인했다. 기존 파서는 조건 문자열과 전체 현재상태를 보존하므로 새 파서/판단기를 만들 근거는 아직 없다. [기존 기능 연결 문서](../../../methodology/fund-management/skill-reuse-and-handoff.md)의 작성·전달 규칙을 보완한다. 원 기업 보고서와 매수 의견은 변경하지 않는다.

기준 커밋은 `b77bbaa4c9440fd670532dce5e93f873af77c7d5`다. [어도비 최종보고서](../../어도비/최종보고서.md)와 [06 리스크 토론](../../어도비/06-리스크토론-비중.md)을 읽었다. 첫 사례인 [MSFT 검증](../20261122-existing-report-handoff/README.md)과 비교했다. 여기의 가격·비중·의견은 원문 기록이며 신규 시장 사실 확인이나 투자 제안이 아니다.

어도비 §7의 '1차 실행 가능' 문구는 원문 기준가 250.23과 1차 가격 250.00 이하 조건을 함께 읽어야 한다. 이 문구만으로 조건 충족을 단정하지 않는다. 현재 가격은 조회하지 않았고 연구 의견도 재판정하지 않았다.

## 실행한 검증

[원시 로그·파싱·입력 해시](evidence.json)에 기록했다.

- report_check: exit 0, 오류 0·경고 1. 경고는 과거 05-교차반론 형식이며 현재 형식으로 과거 보고서를 소급 개작하지 않았다.
- position_plan --parse: exit 0. 최종보고서와 06의 파싱 결과 동일.
- report_audit extract: seed 42, 109개 중 17개 추출, exit 0. 외부 수치 검증/verdict는 미실행.
- 합성 작성 예시: 기존 parse_plan이 두 차수의 괄호 조건과 대기 상태를 보존함을 assertion 3개로 확인. 실제 기업 데이터나 새 단위 테스트 3개가 아니다.
- 이전 55개 테스트 통과는 #111의 기록이며 이번 실행 건수에 포함하지 않는다. Python 동작을 바꾸지 않아 전체 테스트를 재실행하지 않았다.

재현은 기준 커밋에서 evidence.json의 command 배열을 실행한다. 합성 검증은 synthetic_format_check.input을 position_plan.parse_plan에 전달해 기록된 parsed와 비교한다. 계획 일치는 두 보고서의 parse_plan 결과 동등 비교로 확인한다.

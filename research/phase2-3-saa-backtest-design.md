# Phase 2-3 — SAA 전략 비교 및 워크포워드 백테스트 MVP

- 2026-10-28
- 상태: **알고리즘 구현 / 실제 금융 시계열 미확보 / 실데이터 성과 미검증**.
- 의존: Phase 2-1 방법론, Phase 2-2 월간 KRW 총수익률 검증 데이터 계약.
- 정책: IPS v0.4 **DRAFT** (여기서 자동 승인하지 않음).

## 1. 이번 구현

파일 `tools/saa_backtest.py`를 추가했다. Phase 2-2 `tools/saa_data_quality.py`의 월간 입력을 사용해 다음 **5개 연구 전략**을 같은 OOS 구간에서 비교한다.

| 이름 | 연구용 목표 |
| --- | --- |
| `equal` | 동일 비중 기준선 |
| `minvar` | 과거 표본 공분산 기준 최소분산 |
| `shrink_minvar` | 임의 50% 대각 shrinkage 공분산 기준 최소분산 |
| `max_sharpe` | 학습기간 표본평균/분산 기반 샤프 극대화 (`rf=0`) |
| `risk_parity` | 상대 위험기여 비중의 균형 |

구현 방식은 **난수 seed 고정 후보 그리드**(단일자산·쌍별 10% 간격·Dirichlet 유사 난수 후보)를 탐색하는 **근사 비교 MVP**다. 엄밀한 전역 최적화, Ledoit–Wolf 추정, 미래기대수익(CMA), 규제/세금/계좌별 포트폴리오 최적화가 아니다. 후보가 유한하므로 관측된 최적 점수는 진짜 최적해가 아닐 수 있다.

## 2. 실험 설계 및 누수 방지

- **기본 학습 윈도:** 60개월(연구 설정값, 사용자 투자정책 값 아님).
- **OOS:** 첫 60개월 이후 기간. 최초 학습부터 최소 84개월 입력 권장.
- **재배분:** 12개월 간격 목표 비중을 재계산, 그 사이에는 자산 수익률에 따라 비중 drift.
- 각 리밸런싱 시점 `t`에서 **`[t-lookback, t)`만 학습**하고 `t`의 실현 수익은 신호에 넣지 않는다.
- `available_at`에 따라 실제 **월말 주문 가능 시각을 보장하는 로직은 미구현**. Phase 2-2 파일 검증은 `available_at >= as_of` 등 형식만 검사한다. 따라서 **현실에서 거래 가능한 백테스트라고 주장할 수 없다**. 정식 실험 시 관측 월말 시점과 월별 체결 가능 시점의 시차를 반영해야 한다.
- 거래비용 가정은 **거래액 절대 비중 변화의 합 × bps**이며 매수+매도 한도/스프레드/과세와 실제 주식시장 가격 영향은 아직 반영하지 않는다.
- 출력: CAGR, MDD, 변동성, `rf=0` Sharpe, `MAR=0` Sortino, 전체 거래량, 리밸런싱 목표비중. KRW 기준.
- 사용자 자산 실제 수익률·보유데이터가 없으므로 수치 결과를 이 문서에 채우지 않는다.

## 3. 사용

다음 CSV는 Phase 2-2 표준 계약을 따른다(`quality=verified`는 검증된 ingestion에서만 부여해야 함).

```bash
python3 tools/saa_backtest.py --input data/verified_monthly_returns.csv --lookback 60 --rebalance 12 --cost-bps 10 --grid-count 2500 --min-months 84
python3 -m unittest discover -s tools/tests -v
```

검증 실패 시 `BLOCKED`, 정상 연구 결과는 `RESEARCH_ONLY`. `verified` 필드 자체는 서명/원천 증명이 아니며 원본 해시, 데이터 배포 권한과 지수 총수익 구성의 독립 검증은 미구현.

## 4. 결과 판단 원칙

- **한 가지 전략의 Sharpe/Sortino만 높다고 채택하지 않는다.** 과거 상황, 학습기간(36/60/120개월), 비용(예: 0/10/30bps), 시작 시점, 시장 국면, OOS 기간을 바꾸어 민감도 확인.
- 다중 전략·다중 파라미터 탐색에 따른 과최적화 위험을 평가. 연구에 이용하지 않은 마지막 홀드아웃 기간으로 최종 검증.
- 기대수익과 과거 실현 평균 구분. `max_sharpe`는 이 점에서 가장 취약할 수 있다.
- **리스크 패리티 정의:** 분산에 대한 상대 위험기여의 균형. 음의 위험기여나 공분산 특이 행렬이 존재하면 의미가 불안정하므로 검증 단계에서 보고 필요.
- **미포함 항목:** 국별/종목별 익스포저 제약, 계좌별 상품 적격성, 인출/현금흐름, 원화-달러 이중 성과, 레버리지 ETF의 일별 리셋, 실효 노출, 기간별 다른 금리·인플레이션, 상장폐지·매매가능성, 엄밀한 가용시점 처리.
- 결과를 투자정책의 SAA 확정 수치로 자동 승격하지 않는다.

## 5. 추가 실험 전 요구사항

1. **실데이터 공급:** 공식 총수익 지수 또는 배당 포함 ETF 시계열·KRW/USD FX·원화 현금성 수익을 Phase 2-2 데이터 계약에 따라 검증 저장해야 한다.
2. **표본 확보:** 모든 자산군에 동일한 공통 월별 표본구간이 존재해야 한다. ETF 상장 전 시계열은 실거래 ETF 실적이 아닌 `modeled_proxy`임을 표기.
3. **신호 시점 분리:** 발표 지연 및 가격 확정 시점 이후에만 해당 정보를 사용하고 다음 거래가능 시점부터 적용.
4. **정량 제약 설정:** 종목·섹터·레버리지·현금보유/인출·계좌별 투자한도는 사용자 승인 정책에 따라 적용.
5. **다음 Phase 2-4:** 현실적 레버리지/계좌별 상품 배치/인출 시나리오를 포함하여 목표비중의 실제 실현 가능성을 시험.

## 6. 테스트 범위

`tools/tests/test_saa_backtest.py`에서 계산의 결정성, 자산 비중 합계·비음수, 미래 실현수익에 의한 목표비중 누수 방지, 거래비용 반영, 표본 부족 차단을 확인하도록 작성했다. **GitHub CI 실행/테스트 통과는 아직 확인하지 않았다.**

**결론:** Phase 2-3은 전략 비교 엔진의 **연구용 기본 구현**을 추가한 단계이다. **실제 데이터에 대한 성과 비교 및 우수 전략 선정은 아직 수행하지 않았다.**

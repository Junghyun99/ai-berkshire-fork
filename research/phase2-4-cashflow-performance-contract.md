# Phase 2-4 — 현금흐름·TWR/MWR 계약 초안

2026-11-01 KST · DESIGN_DRAFT / RESEARCH_ONLY · 실제 현금흐름 엔진 미구현.
선행: #73 [미결 선택 목록](../reports/policies/decisions-20261101/README.md), [평가계획](../reports/saa/20261101-evaluation-plan/README.md).
IPS v0.4 DRAFT 유지. 이 설계의 병합은 정책 선택·활성화나 주문 승인이 아니다.

## 1. 범위·근거와 기존 엔진

일반계좌·ISA·연금저축·IRP의 통합 범위는 사용자 확인 사항이다. 계좌별 잔고·납입/인출 금액·현금 하한·적격 상품은 미정이다. 이번에는 집계 경계, 이벤트·평가 입력, 계산·차단 규칙을 설계한다. 계좌별 현행 규정과 레버리지 일별 경로는 별도 후속이다.

[GIPS Asset Owners Handbook](https://www.gipsstandards.org/standards/gips-standards-for-asset-owners/gips-standards-handbook-for-asset-owners/) 22.A.21~23, 22.A.29의 공개 설명을 2026-11-01 확인했다. 외부 현금흐름 영향을 제거하는 TWR과 자금의 크기·시기를 반영하는 MWR, 구간 수익률의 기하 연결을 참고했다. 아래 상세 스키마·오류 코드·엄격 모드는 프로젝트 설계 제안이며 GIPS 준수 인증을 주장하지 않는다.

현재 `tools/saa_backtest.py`의 `backtest()`는 월간 자산수익률·목표비중·drift를 사용하고 `performance()`는 초기 NAV=1에서 비용 반영 수익률을 누적한다. 실제 잔고/이벤트·현금 계정·계좌 적격성·MWR 입력은 없다. 최초 매수 비용도 제외한다. 이 인터페이스와 기존 실험 결과를 보존하고 별도 모듈/adapter를 추가하는 방향이다. 월간 TR을 일별로 보간해 납입 시점 평가액을 만들지 않는다.

## 2. 범위와 회계 불변조건

`scope_id`, `scope_version`, 포함된 익명 계좌 ID, 적용 시작/종료, 주 KRW·보조 USD를 고정한다. 계좌 추가·제외는 과거를 소급 재분류하지 않고 새 범위 버전으로 계산한다. 계좌번호·개인 원본·API 키는 공개 저장소에 넣지 않는다.

| 이벤트 | 계좌 단위 | 통합 단위 |
| --- | --- | --- |
| 범위 밖에서 입금/범위 밖으로 인출 | 외부 흐름 | 외부 흐름 |
| 포함 계좌 A→B 이전 | A 인출·B 입금 | 내부 이동, 외부 흐름 0 |
| 범위 밖 계좌로 이전 | 출금 | 외부 인출; 같은 사람 소유라도 범위 기준 |
| 자산 매매·환전 | 현금/자산 교환 | 내부 거래; 수수료·스프레드는 비용 |
| 배당·이자 | 투자소득 | 외부 납입 아님; 외부 계좌로 지급하면 소득 인식 후 외부 인출을 별도 기록 |
| 수수료·원천징수 | 비용/세금 | 외부 인출로 제거하지 않음; 별도 비용 기준 표시 |

통합 NAV는 포함 계좌의 자산·현금·근거 있는 미수금에서 부채를 차감한다. 이전 출금과 입금 사이에는 소유권이 유지되는 금액을 이체중 자산으로 추적한다. 미수금과 도착 현금을 동시에 계상하지 않는다. 한쪽 다리 누락·금액 차이·소유권 불명은 해결 전 BLOCKED다. 동일 통화 이전은 금액 상쇄를 확인하며 수수료는 별도 비용이다. 이종 통화 이전은 단순 숫자 합 0을 요구하지 않고 환전 체결·각 통화 원장·FX 평가·비용을 대조한다.

현금 지급능력은 NAV와 다르다. 정산 전 현금·인출 제한 계좌·이체중 자산을 즉시 쓸 수 있는 현금으로 세지 않는다. 예정 납입은 실제 잔고에 포함하지 않는다. 현금 부족 시 차입·강제 매도·인출 연기를 자동 가정하지 않고 `LIQUIDITY_SHORTFALL`을 반환한다.

## 3. 입력 계약 v0.1 후보

금액·수량·환율은 유한한 decimal 문자열로 입력하며 bool/NaN/Infinity를 거부한다. 허용 오차·반올림 통화 규칙을 manifest에 버전 고정한다. 금액에는 통화가 필수이고 집계 전에 통화를 통일한다.

| 레코드 | 필수 정보·검증 |
| --- | --- |
| 공통 | schema_version, record_id, source_ref, source_hash, retrieval_at, quality(actual_observed / research_proxy / synthetic_fixture), revision_id, supersedes_id(해당 시) |
| scope | scope_id/version, 익명 account_id와 account_type, 포함 기간, valuation_timezone, valuation_clock, currency, cost_tax_basis |
| cash_event | event_id, account_id, kind, signed_amount, currency, economic_at, settled_at(미정 허용), funds_available_at(미정 허용), available_at, transfer_id(이전 필수), sequence(동일 시각 순서), status(actual/planned) |
| valuation | valuation_id, scope/account, valuation_at, side(before_flow/after_flow/period_boundary), event_group_id, NAV와 현금/자산/미수/부채 구성, price/FX 근거·시각·available_at |
| FX | base_currency, quote_currency, positive rate, observed_at, available_at, source_ref/hash, 환산 규칙 버전 |

`economic_at`은 경제적 흐름 발생시각, `available_at`은 그 기록을 알 수 있었던 시각, `funds_available_at`은 매매/인출에 쓸 수 있는 시각이다. 세 시각을 대체하지 않는다. 관측 이후 수정 내역은 원본 덮어쓰기 대신 새 revision으로 보존한다. #54 선택기는 해당 레코드 형태와 adapter 검증을 거쳐 연결해야 하며 현재 연결되어 있지 않다.

정확 TWR에는 timezone-aware 시각 및 흐름과 평가의 순서가 필요하다. 날짜만 있는 외부 흐름은 별도 `date_precision=day` 입력으로 보존하고 정확 모드는 차단한다. 일자 기반 MWR은 명시한 평가 timezone의 달력 날짜로 계산할 수 있지만 거래가능 시각 증거로 전용하지 않는다. 이 일자 모드는 기존 #54 시각 검사 규칙을 완화하는 것이 아니다.

중복 event_id/revision은 내용이 같으면 한 번만 집계하고 다르면 충돌이다. 동일 시각의 여러 흐름은 명시된 group/sequence에 따라 한 묶음으로 평가하며, 전후 NAV 사이에 가격 변동·비용이 끼면 이를 별도 구간으로 분리한다. 정확 모드에서 순서를 알 수 없으면 임의 정렬하지 않는다.

## 4. TWR: 흐름 전후 평가로 단위가치 연결

통합 범위로 들어오는 외부 흐름 F는 양수, 나가는 흐름은 음수다. 시작 NAV는 시작시각의 흐름을 이미 반영한 V0_plus로 정하고, 이후 흐름 시점 j에서 Vj_minus(직전), Vj_plus(직후)를 기록한다. 흐름만 있는 순간에는 `Vj_plus = Vj_minus + Fj`다. 비용이 있으면 별도 비용 이벤트/평가 단계로 분리해 수익률에서 빠지지 않게 한다. 종료 NAV는 종료시각 외부 흐름 직후로 고정하며 마지막 흐름의 전후 평가도 필요하다.

흐름 없는 각 구간 `rj = Vj_minus / Vprevious_plus - 1`; 마지막 흐름 뒤부터 종료까지도 같은 식을 적용한다. `TWR = product(1+rj)-1`. 외부 흐름은 단위 수를 바꾸고 단위가치는 바꾸지 않는 unitization으로 독립 대조할 수 있다. 계좌별 TWR의 산술평균 대신 통합 NAV와 외부 흐름으로 다시 계산한다.

- 구간 시작 NAV≤0, 미평가 자산, 전후 NAV 누락, 흐름 정합 오차 초과: `BLOCKED`, 정확 TWR=null.
- 전액 인출로 NAV=0이면 해당 운용 구간을 종료한다. 이후 신규 납입은 별도 segment이며 0으로 나누거나 공백을 0%로 메우지 않는다. 시장손실로 0에 도달하는 사례는 -100% 종결로 구분하며 이후 연속 운용을 가정하지 않는다.
- 근사 Modified Dietz는 별도 opt-in 연구 모드 후보다. `R=(VE-VB-sum(F))/(VB+sum(wF))`, `w=(tE-tF)/(tE-tB)`; VB는 시작 흐름 후, VE는 종료 흐름 후, 포함 흐름 범위는 `(tB,tE]`. 분모≤0 또는 시간정보 부족이면 null. `approximation=true`로 표시하고 정확 TWR 대체·자동 fallback 금지. 큰 흐름 임계값은 미정이며 정확 모드는 모든 흐름 평가를 요구한다.
- 입출금으로 늘어난 잔고의 `VE/VB`를 CAGR로 부르지 않는다. 순수 성과 MDD는 TWR 단위가치로, 실제 잔고 감소·인출 충족률은 별도 지표로 보고한다. 월말 MDD와 일별 MDD를 구분한다.

## 5. MWR: 투자자 관점의 현금흐름

측정 시작 시점의 NAV를 투자자의 초기 지출 `C0=-V0`로 둔다. 여기서 V0는 시작 흐름 후 NAV이므로 시작 이전/동시 흐름을 다시 더하지 않는다. 이후 `(t0,T]` 범위의 외부 납입은 음수, 인출은 양수다. 종료시각 흐름 직후 NAV를 최종 양수 잔존가치로 더한다. 종료일의 인출과 잔존 NAV는 별개이며 중복 계상하지 않는다. 동일 날짜 흐름은 합산한다. 내부 이전·배당·이자는 외부 흐름에 넣지 않고 NAV에서 반영한다.

연율 r에 대해 `sum(Ci / (1+r)^((di-d0)/365)) = 0`, `r > -1`을 푸는 ACT/365F 일자 규칙을 제안한다. 달력 날짜는 명시한 valuation_timezone에서 얻는다. 모든 금액과 종료 NAV를 각각 해당 시점 FX로 KRW 및 USD로 환산한 뒤 두 계산을 독립 수행한다. KRW MWR을 마지막 환율로 나누지 않는다.

해법 계약: 합산 후 양·음 흐름이 모두 있어야 한다. 일자 순 부호 변화가 1회이면 유일근 성질을 이용하되 브래킷·허용오차·잔차·반복한도를 기록한다. 부호 변화가 여러 번이면 첫 Newton 해를 채택하지 않고 기본 모드 `AMBIGUOUS_CASHFLOW_PATTERN`, mwr=null로 보낸다. 여러 부호 변화가 언제나 여러 해를 뜻하는 것은 아니며 일반 해석 모드는 후속 연구다. 탐색 범위 내 브래킷 실패는 `ROOT_NOT_BRACKETED`로 기록하고 수학적으로 해가 없다는 뜻으로 바꾸지 않는다. 불수렴은 `NOT_CONVERGED`다.

1년 미만은 연율 값을 대표 성과로 내세우지 않고 `period_mwr=(1+r)^(days/365)-1`와 기간을 주 표시한다. 0일 기간은 미정. 1년 이상도 연율/누적/기간을 명시한다. solver 구현과 수치 안정성 테스트는 후속이다.

## 6. 비용·자료·미래정보 경계

계좌 비용이 NAV에 반영되면 `performance()`의 비용 차감을 다시 적용하지 않는다. 원천징수 반영값을 모든 세금을 반영한 세후 성과라 하지 않고 `observed_withholding_only` 등 계산 범위를 기록한다. 외부 지급 비용도 투자자 부담 기준 포함 여부와 자금 원천을 명시해야 한다. 미확인 비용을 0으로 묵인하지 않는다.

배당 포함 TR 입력으로 이미 소득을 반영한 경로에는 배당 현금 이벤트를 추가하지 않는다. 원가격+배당 현금 원장 또는 TR 기반 가상 경로 중 하나의 회계 방식을 고정하고 후자는 실제 계좌 성과와 구분한다.

사후 성과평가는 당시 발생 흐름의 나중 수집본으로 재구성할 수 있지만 `restated_as_of`와 해시를 남긴다. 전략 의사결정에는 decision_at까지 알려진 기록만 사용한다. 실제 납입이 사후 확인되었다고 과거 매수 신호에 미리 반영하지 않는다. 계획된 미래 납입은 시나리오 입력이며 실측과 별도 결과로 출력한다.

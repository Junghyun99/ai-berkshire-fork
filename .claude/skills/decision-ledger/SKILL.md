# 투자 판단 원장: 기록 → 정산 → 회고

$ARGUMENTS 에 대해 판단 원장 작업을 수행한다. 인자가 없으면 **정산 → 회고 → 집계** 전체를 수행한다.

**지원하는 입력 형식**:
- (없음) 또는 `정산` — 평가 시점이 지난 판단을 채점하고, 새로 채점된 건마다 회고를 작성
- `회사명` 또는 `티커` — 그 종목의 과거 판단·결과·회고 조회
- `집계` — 판단별 적중률, 확신도 보정, 스킬별 비교, 운/실력 4분면

> "자신의 실수를 기록하지 않는 투자자는 같은 실수를 반복한다." — 멍거의 취지
>
> "결과가 좋았다고 판단이 옳았던 것은 아니다. 운과 실력을 구분하라." — 리루의 취지

## 왜 하는가

리포트가 쌓여도 "그 판단이 맞았는가"를 재지 않으면 리서치 품질이 나아지는지 알 수 없다.
- **앞으로 쓰는 리포트만** 기록·채점한다. 과거 날짜로 되돌아가 판단하는 백테스트와 달리, LLM이 학습 데이터로 미래를 이미 알고 있는 문제가 없다.
- 가치투자 판단이라 평가 창이 길다: **12개월이 주 평가**, 3·6개월은 참고, 36개월은 장기 검증.
- 주가만 보면 운과 실력이 섞인다. 그래서 **주가(알파)와 논지(반증 조건 발생 여부)를 따로** 채점한다.

설계 출처: TradingAgents(Apache 2.0)의 결정 기록·정산·반성 루프를 가치투자 리포트용으로 변형(`research/tradingagents/` 참고).

## 도구

`tools/decision_ledger.py` (stdlib만, 가격은 Yahoo Finance 수정종가)

| 명령 | 용도 |
|---|---|
| `add` | 리포트 판단 기록 (리서치 스킬 마지막 단계에서 호출) |
| `settle` | 평가 시점이 지난 판단 채점 |
| `review` | 채점 결과에 논지 상태·회고 기록 |
| `show {티커\|종목명}` | 종목의 과거 판단·결과·회고 |
| `summary` | 집계 |
| `list` | 전체 목록 |

저장: `reports/decision-ledger.csv`(판단, 추가만) · `reports/decision-outcomes.csv`(채점·회고)

## 1. 기록 규칙 (리서치 스킬이 따르는 공통 규칙)

### 1-1. 결론 라벨 줄 (보고서 결론부 맨 앞, 형식 고정)

```
**판단**: 매수 | **확신도**: ★★★★ | **내재가치**: 180,000~220,000원 | **반증 조건**: HBM 점유율 40% 미만
```

- **판단**은 `매수` / `관망` / `회피` 셋 중 정확히 하나. "조건부 매수", "분할 매수 검토" 같은 변형은 쓰지 않는다. 조건은 본문에 쓰고 라벨은 셋 중 하나로 고른다.
  - 매수: 지금 가격에서 사는 쪽이 낫다
  - 관망: 좋은 회사일 수 있으나 지금 가격·정보로는 판단 보류 (방향 주장 없음 → 적중률 채점 안 함)
  - 회피: 사지 않는 쪽이 낫다 (벤치마크보다 못할 것이라는 주장)
- **확신도**는 ★1~5 (반 별 없음). 확신도가 실제 적중과 맞는지 나중에 보정한다.
- **내재가치**는 현지 통화 가격 범위. 산출하지 못했으면 `-`.
- **반증 조건**은 "이게 보이면 논지가 틀린 것"인 관찰 가능한 사실 1~3개. thesis-tracker의 레드라인과 같은 것을 쓴다.
- 이 줄의 라벨(`**판단**:` 등)은 바꾸지 않는다. 사람이 아니라 도구가 읽는 줄이다.

### 1-2. 원장 기록 (보고서 저장·표본 검사 통과 후)

```bash
python3 tools/decision_ledger.py add \
  --ticker {종목코드} --name {회사명} --skill {스킬명} \
  --report {보고서 경로} --verdict {매수|관망|회피} --conviction {1-5} \
  --iv-low {내재가치 하단} --iv-high {내재가치 상단} \
  --thesis "{핵심 논지 한 줄}" --falsifier "{반증 조건}"
```

- `--ticker`: 한국 6자리(005930), 미국 티커(AAPL), 홍콩 숫자(0700) — `global_stock_data.py`와 같은 규칙
- 기록일은 오늘. **진입가는 다음 거래일 종가**로 정산 때 확정된다(리포트 작성 후 나온 정보를 봤을 수 있으므로 당일 종가를 쓰지 않는다).
- 같은 날·같은 종목·같은 스킬은 한 번만 기록된다(중복 시 거부). 보고서를 고쳐 다시 내도 원장은 그대로 둔다.
- 비상장·매수 불가 종목은 기록하지 않는다.
- 다중 회사 보고서(체크리스트 비교 등)는 회사마다 한 줄씩 기록한다.

### 1-3. 리서치 전 과거 판단 확인

같은 종목을 다시 리서치할 때는 데이터 수집 전에 먼저 실행한다:

```bash
python3 tools/decision_ledger.py show {티커}
```

과거 판단·결과·회고가 있으면 보고서의 "과거 판단과의 비교" 항목에 반영한다: 무엇이 바뀌었는가, 지난 교훈을 이번 분석에 어떻게 적용했는가. 결과에 끌려 입장을 바꾸지 않는다 — 논지가 바뀐 근거(사실)를 적는다.

## 2. 정산

```bash
python3 tools/decision_ledger.py settle
```

- 기간이 다 거래되지 않은 구간은 건드리지 않는다(조기 정산 금지).
- 알파 = 종목 수익률 − 벤치마크 수익률. 둘 다 수정종가(배당·분할 반영).
  - 벤치마크: KOSPI 069500.KS, KOSDAQ 229200.KS, 미국 SPY, 홍콩 2800.HK, 중국 510300.SS, 일본 1306.T
- 방향 적중: 매수는 알파 > 0, 회피는 알파 < 0. 관망은 채점하지 않는다.
- 내재가치 위치: 평가일 종가가 기록한 범위의 하단 미만 / 범위 안 / 상단 초과.
- 출력 첫 줄이 `UNAVAILABLE`이거나 실패 건이 있으면 **수익률을 추정해 채우지 않는다**. 다음 정산 때 다시 시도한다.

## 3. 회고 (새로 채점된 건마다)

1. 원 보고서와 원장의 반증 조건을 다시 읽는다.
2. 반증 조건이 실제로 발생했는지 확인한다(최신 실적·공시, 필요하면 `/thesis-tracker`).
3. 기록한다:

```bash
python3 tools/decision_ledger.py review --id {id} --horizon {3M|6M|12M|36M} \
  --thesis-status {유지|훼손|불명} \
  --note "{2~4문장}"
```

**회고 문장 규칙** (TradingAgents Reflector 형식):
1. 수치가 판단에 대해 말해주는 것(알파 인용). **창이 짧아 논지를 판단할 수 없으면 그렇다고 쓴다** — 12개월 논지가 3개월 주가로 반증되지는 않는다.
2. 논지 중 어느 부분이 사실로 지지/훼손됐는가(데이터로).
3. 다음 유사 분석에 적용할 **구체적 교훈 1개**.
- 불릿·헤더 없이 평문. 다음 리서치 때 그대로 다시 읽히므로 군더더기 없이.
- 결과가 좋았어도 논지가 훼손됐으면 `훼손`이다(운). 결과가 나빠도 논지가 유지되면 `유지`다(인내 구간).

## 4. 집계 (분기 1회 권장)

```bash
python3 tools/decision_ledger.py summary
```

보고 형식:

| 항목 | 질문 |
|---|---|
| 판단별 | 매수의 평균 알파 > 0인가? 회피 종목은 실제로 부진했는가? 관망 종목의 알파 크기(놓친 기회 또는 피한 손실)는? |
| 확신도 보정 | ★5가 ★3보다 실제로 더 잘 맞았는가? 아니라면 확신도 표기가 정보를 담고 있지 않다는 뜻 |
| 스킬별 | investment-team이 investment-research·checklist보다 나은가? |
| 운/실력 4분면 | `운`(논지 훼손인데 주가 적중)이 많으면 좋은 결과를 실력으로 착각하고 있는 것 |

**4분면**:

| | 판단 방향대로 (알파 적중) | 반대로 |
|---|---|---|
| 논지 유지 | 실력 | 인내 구간 (시장이 아직 모름) |
| 논지 훼손 | **운** (가장 위험) | 오판 |

집계 결과는 "사실"과 "관점"을 구분해 요약하고, 표본이 적으면(구간별 10건 미만) "표본 부족, 결론 보류"라고 명시한다.

## 핵심 원칙

- **기록은 판단 시점에, 수정 없이**: 원장(`decision-ledger.csv`)은 추가만 한다. 지난 판단을 고치면 채점이 무의미해진다.
- **결과로 판단을 미화하지 않는다**: 운과 실력을 분리하는 것이 이 원장의 목적이다.
- **데이터 없음은 데이터 없음으로**: 가격 조회 실패를 추정치로 메우지 않는다.

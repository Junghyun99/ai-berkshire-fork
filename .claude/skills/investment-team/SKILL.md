# 투자 리서치 팀: 4개 역할 병렬 분석 프레임워크

$ARGUMENTS 에 대해 팀 기반 투자 리서치 분석을 수행한다. Team 도구로 진짜 멀티 Agent 병렬 리서치 팀을 만든다.

## 실행 절차

### 1단계: 팀 프레임워크 제시

먼저 `python3 tools/decision_ledger.py show {티커}` 로 이 종목의 과거 판단·결과·회고를 확인한다. 기록이 있으면 4개 Agent의 스폰 프롬프트에 요약을 넣고(지난 반증 조건이 발생했는지 각 관점에서 점검하도록), 최종 보고서에 비교를 쓴다. 규칙: `.claude/skills/decision-ledger/SKILL.md` 1-3.

이어서 종목을 넘어선 과거 교훈을 꺼낸다(규칙: 같은 문서 1-4):
```bash
python3 tools/decision_ledger.py lessons --ticker {티커} --tag {산업} --tag {테마} --market {시장}
```
출력 전체를 4개 Agent의 스폰 프롬프트 `**과거 교훈**` 칸에 넣는다. 결과가 없으면(종료 코드 3) 그 칸에 "(해당 교훈 없음)"이라고 적는다.

사용자에게 아래 팀 구조를 보여주고, 확인 후 시작한다. 4대 거장은 **여러 스킬이 공유하는 재사용 페르소나 정의(`.claude/agents/master-*.md`)**이며, 아래 `subagent_type`으로 스폰하면 지침·모델이 그대로 적용된다. 이 스킬 고유의 분석 프레임(3단계 태스크 내용)은 스폰 프롬프트로 전달한다.

| 역할 | subagent_type | 모델 | 책임 | 분석 프레임워크 |
|------|--------------|------|------|----------|
| **team-lead** (본인) | — (오케스트레이터) | 세션 모델 | 총괄 조율, 종합 판단, 최종 보고서 출력 | 4대 거장 종합 |
| **business-analyst** | `master-duan` | opus | 비즈니스 모델 & 해자 분석 | 돤융핑 관점 |
| **financial-analyst** | `master-buffett` | opus | 재무제표 & 밸류에이션 분석 | 버핏 관점 |
| **industry-researcher** | `master-munger` | opus | 산업 구도 & 경쟁 상황 | 멍거 관점 |
| **risk-assessor** | `master-lilu` | opus | 리스크 평가 & 경영진 판단 | 리루 관점 |
| risk-aggressive / risk-conservative / risk-neutral | `risk-aggressive` / `risk-conservative` / `risk-neutral` | sonnet | 7.5단계 리스크 토론: 정해진 판단의 실행 계획(비중·분할 매수·축소) 조정 | 공격·보수·중립 |

### 1.5단계: AI 리서치 편향 평가

팀 생성 전, 해당 회사의 "AI 리서치 가능성" 평가를 사용자에게 먼저 보여준다:

**정보 풍부도 등급** (리서치 전략을 결정):
| 등급 | 특징 | 리서치 전략 조정 |
|------|------|------------|
| A등급 (정보 풍부) | 상장 오래됨, 증권사 커버리지 넓음 | 팀의 초점을 **반대편 검증**과 **비컨센서스 관점**에 둔다. 시장과 일치하는 "맞는 말이지만 쓸모없는 소리" 출력을 피한다 |
| B등급 (정보 보통) | 상장 얼마 안 됨, 커버리지 제한적 | 각 Agent의 추정 데이터에 신뢰도를 표기하고, team-lead가 취합 시 "데이터 충분도"를 표기 |
| C등급 (정보 희소) | 비주류/신규 상장/신흥 시장 | 팀을 "제1원리 모드"로 전환: 보고서 완결성을 추구하지 말고 사업 본질의 핵심 질문 몇 가지에 집중 |

**핵심 유의점**: 자료가 많다 ≠ 확실성이 높다, 자료가 적다 ≠ 확실성이 낮다. AI가 출력할 수 있는 신뢰도 ≠ 투자의 진짜 확실성. 확실성은 비즈니스 모델 자체에서 나오지, 자료의 양에서 나오지 않는다.

등급 결과를 각 Agent에게 알려 리서치 방식에 반영시킨다.

### 1.6단계: 팩트시트(확정 수치표) 생성

팀 생성 전에 핵심 수치를 도구로 한 번에 뽑아 **모든 Agent가 같은 기준값**을 쓰게 한다:

```bash
python3 tools/fact_sheet.py {종목코드}
```

- 시세·밸류에이션, 최근 3년 재무, 같은 통화끼리 계산한 비율, 1차 출처(DART·네이버·SEC) 교차 검증이 한 표에 나온다.
- 한국 종목은 DART 주식 총수로 보통주·우선주·자기주식을 나눠, 우선주를 포함한 시총·EPS·BPS·PER·PBR을 따로 낸다. 주당 지표는 이 값을 쓰고, Yahoo 발행주식수·PER·PBR은 참고로만 쓴다(우선주 처리 기준이 불분명).
- 출력 전체를 4개 Agent의 스폰 프롬프트에 그대로 넣고, 최종 보고서 부록에도 붙인다(별도 파일로 저장하지 않음).
- ❌ 판정 항목, `데이터 없음` 항목, 통화 경고는 사용자에게 먼저 알린다.
- 현재 시점 스냅샷이다. 과거 시점 분석이면 이 표 대신 `dart_data.py` / `sec_edgar_data.py` 의 `--as-of` 결과를 기준값으로 쓴다.

설계 출처: TradingAgents의 `get_verified_market_snapshot` — LLM이 숫자를 지어내는 문제를 결정론적 기준값으로 막는다.

### 2단계: 팀 생성

TeamCreate로 팀을 만든다:
- team_name: `{회사명}-research` (영문 소문자, 예: `meituan-research`)
- agent_type: `team-lead`

### 3단계: 4개 태스크 생성

TaskCreate로 아래 4개 태스크를 만든다 (각각 subject, description, activeForm 포함):

#### 태스크 1: 비즈니스 모델 분석
- subject: `{회사명}의 비즈니스 모델, 해자, 사용자 가치 분석`
- description 포함 내용:
  1. 비즈니스 모델 본질: 핵심 사업 정의, 수익 구조 분해
  2. 플랫폼/제품 플라이휠 효과가 어떻게 돌아가는가
  3. 해자 분석: 브랜드/전환비용/네트워크 효과/규모의 경제/기술 장벽을 하나씩 검증
  4. 사용자/고객 가치: 각 이해관계자에게 어떤 고유 가치를 창출하는가
  5. 사업 매트릭스와 시너지 효과
  6. 돤융핑의 "좋은 사업" 기준 평가: 차별화, 가격결정력, 지속 가능한 경쟁 우위
  7. 최신 실적, 산업 보고서 등 공개 정보 검색 필수

#### 태스크 2: 재무 및 밸류에이션 분석
- subject: `{회사명}의 재무 데이터, 수익성, 밸류에이션 분석`
- description 포함 내용:
  1. 최근 3-5년 매출, 순이익, 영업이익 추세
  2. 수익성 지표: ROE, ROA, 매출총이익률, 영업이익률
  3. 현금흐름 분석: 영업현금흐름, 잉여현금흐름, 자본지출
  4. 재무상태표 건강도: 현금 보유, 부채비율, 유동성
  5. 밸류에이션 분석: PER/PSR/PBR/EV 등, 과거 및 동종업계 대비
  6. 안전마진 평가: 내재가치 vs 현재 주가
  7. **재무 엄밀성 검증 (반드시 Bash로 도구 호출, 암산 금지)**:
     - 시가총액 검산: `python3 tools/financial_rigor.py verify-market-cap --price {가격} --shares {주식수} --reported {보고된 시총} --currency {통화}`
     - 밸류에이션 검산: `python3 tools/financial_rigor.py verify-valuation --price {가격} --eps {EPS} --bvps {주당순자산}`
     - 핵심 데이터 교차 검증: `python3 tools/financial_rigor.py cross-validate --field {필드} --values '{JSON}' --unit {단위}`
     - 3개 시나리오 밸류에이션: `python3 tools/financial_rigor.py three-scenario --price {가격} --eps {EPS} --shares {주식수(억)} --growth {낙관} {중립} {비관} --pe {낙관PE} {중립PE} {비관PE}`
     - 도구 출력 결과를 검증 기록으로 보고서에 그대로 삽입

#### 태스크 3: 산업 및 경쟁 분석
- subject: `{산업} 산업 구도와 {회사명}의 경쟁 상황 분석`
- description 포함 내용:
  1. 산업 규모와 성장: 시장 규모, 성장률, 침투율
  2. 경쟁 구도: 주요 경쟁사 시장 점유율, 경쟁 전략 비교
  3. 핵심 경쟁자 위협 평가: 주요 경쟁사를 하나씩 분석
  4. 세부 분야별 구도
  5. 산업 트렌드: 기술 변화, 정책 영향, 신규 진입자
  6. 밸류체인 분석: 상·중·하류 가치 배분
  7. 최신 산업 데이터와 경쟁 동향 검색 필수

#### 태스크 4: 리스크 및 경영진 평가
- subject: `{회사명}의 투자 리스크와 경영진 품질 평가`
- description 포함 내용:
  1. 경영진 평가: CEO의 능력 범위, 정직성, 전략적 안목, 자본 배분 능력, 과거 의사결정의 질
  2. 규제 리스크: 현재 및 잠재적 규제 영향
  3. 경쟁 리스크: 각 경쟁사의 위협 수준 평가
  4. 사업 리스크: 신사업 적자, 확장 불확실성
  5. 거시 리스크: 경기 사이클, 산업 사이클 영향
  6. 지배구조: 지분 구조, 특수관계자 거래, 주주환원 정책. 한국 종목은 `python3 tools/dart_data.py insiders {종목코드} --days 180` 과 `major-holders {종목코드}` 로 내부자·5% 보유자 지분 변동을 1차 공시로 확인한다(증감 사유는 원문 링크로 확인, 주식보상 증가를 매수로 읽지 않는다). 미국 종목은 `alphavantage_data.py insider {티커}`
  7. 장기 확실성: 10년 후 이 회사는 어떤 모습일까? 무엇이 비즈니스 모델을 무너뜨릴 수 있는가?
  8. 최신 규제 동향, 경영진 발언 등 검색 필수

### 4단계: 4개 Agent 병렬 실행

Task 도구로 4개 Agent를 동시에 실행한다 (**반드시 같은 메시지에서 병렬 호출**):

각 Agent의 설정:
- `subagent_type`: 역할별 재사용 페르소나 정의 — business-analyst→`master-duan`, financial-analyst→`master-buffett`, industry-researcher→`master-munger`, risk-assessor→`master-lilu` (거장 페르소나·모델은 정의 파일이 담당하므로, 프롬프트에는 아래 태스크 내용만 전달)
- `run_in_background`: `true`
- `team_name`: 해당 팀 이름
- `name`: 해당 역할명 (business-analyst / financial-analyst / industry-researcher / risk-assessor)
- **폴백**: `master-*` 정의가 로드되지 않은 환경이면 `subagent_type: general-purpose`로 스폰하되 아래 prompt 템플릿에 거장 관점을 명시해 전달한다.

각 Agent의 prompt 템플릿:

```
당신은 {회사명} 투자 리서치 팀의 "{역할명}"으로, {거장 이름}의 투자 관점에서 {회사명}을 분석한다.

태스크 #{태스크 번호}를 완료하라: {태스크 subject}

구체적 요구사항:
{태스크 description의 내용}

**기준 수치(팩트시트)**:
{1.6단계 fact_sheet.py 출력 전체}
- 정확한 수치(주가·시총·매출·이익·현금흐름·비율)는 이 표가 기준이다. 다른 출처 값이 다르면 **불일치로 표기**하고, 두 값을 맞춘 숫자를 만들지 않는다.
- 표의 `데이터 없음`은 추정으로 채우지 않는다. 다른 출처에서 찾으면 출처를 붙인다.
- 주가 통화와 재무 통화가 다르면 섞어 계산하지 않는다(환산 시 환율·기준일 명시).

**과거 판단**:
{decision_ledger.py show 결과 요약. 기록이 없으면 이 줄에 "(이 종목의 과거 판단 기록 없음 — 비교 생략)"이라고 적는다. 빈칸으로 두지 않는다}

**과거 교훈 (점검 항목, 결론 아님)**:
{decision_ledger.py lessons 출력. 없으면 "(해당 교훈 없음)"}
- 각 교훈이 이 종목·이 관점에 해당하는지 데이터로 확인하고, 해당하면 분석에 어떻게 반영했는지 보고서에 한 줄로 적는다. 해당하지 않으면 생략해도 된다.
- 교훈 하나만으로 관점 판단의 방향을 정하지 않는다.

**리서치 방법**:
- WebSearch로 최신 공개 정보(실적, 산업 보고서, 뉴스)를 검색
- **재무 데이터는 반드시 두 개의 독립 출처에서** 가져올 것. `.claude/skills/financial-data/SKILL.md` 규범에 따라 실행 (미국 주식: macrotrends+stockanalysis; 홍콩 주식: aastocks+macrotrends; 중국 A주: East Money+cninfo; 한국 주식: DART+네이버 금융). 두 출처 간 오차 >1%는 표기
- 데이터 정확성 확보, 핵심 데이터에 출처 표기
- 분석은 깊이 있게, 겉핥기 금지

**출력 요구사항**:
- 보고서는 상세하게, 핵심 데이터는 Markdown 표로 제시
- 각 분석 차원마다 명확한 결론과 점수
- 보고서 말미에 해당 차원의 종합 결론
- 맨 마지막 줄에 이 관점의 입장을 한 줄로: `**관점 판단**: 매수|관망|회피 — {한 문장 이유}` (교차 반론 라운드에서 쓴다)

**완료 후**:
1. TaskUpdate로 태스크 #{태스크 번호}를 completed로 표시
2. SendMessage로 전체 분석 보고서를 team-lead에게 전송 (type: "message", recipient: "team-lead")
```

### 5단계: 보고서 수신 및 진행 추적

- 사용자에게 진행 표를 실시간으로 보여준다 (어느 Agent가 완료됐고 어느 Agent가 아직 리서치 중인지)
- 보고서를 하나 받을 때마다 진행 상황을 갱신하고 그 보고서의 핵심 요점(3-5개)을 보여준다
- 4개 보고서가 모두 도착할 때까지 대기

### 5.5단계: 교차 반론 라운드 (1라운드)

4개 보고서는 각자 독립적으로 쓰여서 서로의 약점을 공격하지 않는다. 종합 전에 한 라운드 반론을 거쳐 "양면 제시" 원칙을 구조로 강제한다.

설계 출처: TradingAgents의 Bull/Bear 토론(상대의 직전 주장을 데이터로 반박) + 빈 입력 표식.

**1. Team Lead가 주장 요약을 만든다** — 보고서마다:
- 관점 판단(`**관점 판단**:` 줄)
- 핵심 주장 3개, 각 주장의 근거 수치와 출처

**2. 각 Agent에게 다른 세 관점의 요약을 보낸다** (SendMessage, 4개 동시):

```
교차 반론 라운드다. 아래는 다른 세 관점의 판단과 핵심 주장이다.

{다른 세 관점 요약. 당신과 판단이 다른 관점이 하나도 없으면 이 줄에
"(반대 판단을 낸 관점이 없다 — 대신 당신 논거에서 가장 약한 고리를 스스로 공격하라)"라고 적는다}

다음 세 가지를 600자 안에서 답하라:
1. 반박: 당신의 판단과 충돌하는 주장 중 가장 강한 것 최대 3개를 골라 데이터로 반박한다.
   - 위 요약에 실제로 있는 주장만 반박한다. 상대가 하지 않은 주장을 지어내지 않는다.
   - 수치는 팩트시트 또는 출처가 붙은 데이터로만.
2. 인정: 상대 주장 중 맞다고 보는 것과, 그로 인해 당신 결론에서 수정할 부분.
3. 최종 관점 판단: 유지 또는 변경(`**관점 판단**: ...` 한 줄)과 그 이유.
원 보고서는 고치지 않는다. 답은 SendMessage로 team-lead에게 보낸다.
```

**3. Team Lead가 `reports/{회사명}/05-교차반론.md`로 저장한다** — 관점별 반박·인정·최종 판단, 그리고 판단이 바뀐 관점과 그 이유.

- 반론으로 관점 판단이 바뀌었으면 7단계 종합에서 **바뀐 판단과 바뀐 이유**를 쓴다.
- 폴백: 팀 도구가 없거나 Agent가 이미 종료됐으면 team-lead가 네 관점의 반론을 순차로 작성하되, 위 규칙(요약에 있는 주장만, 데이터로만)을 그대로 지킨다.

### 7단계: 최종 보고서 종합

2. 더 강한 쪽에 서고, **얼마나 분명하게 이겼는지로 확신도(★)를 정한다.** 근소하게 이기면 ★2~3, 압도적이면 ★4~5.

### 7.5단계: 리스크 토론과 실행 계획 (TradingAgents 리스크 팀 → Portfolio Manager)

7단계에서 결론 라벨 줄(판단·확신도·내재가치·반증 조건)을 정한 뒤, **"그 판단을 어떻게 실행할까"**를 세 성향이 다툰다. 판단 자체를 다시 뒤집는 단계가 아니다.

**1) 기준선 계산** — 숫자를 지어내지 않도록 규칙으로 출발점을 만든다:
```bash
python3 tools/position_plan.py --from-report reports/{회사명}/최종보고서.md --ticker {종목코드} [--current-weight {보유 비중}]
```
- 비중 상한 = 최대 비중 10% × 확신도 계수(★1 0 / ★2 0.25 / ★3 0.5 / ★4 0.75 / ★5 1.0), 회피면 0
- 분할 매수 = 내재가치 중앙값 × (1 − 안전마진 15/25/35%), 배분 30/30/40%
- 축소 검토 = 내재가치 상단 × 1.2 이상, 또는 반증 조건 발생
- 보유 비중을 알면(`reports/portfolio-latest.md` 또는 사용자 입력) `--current-weight` 로 넣는다. 모르면 "보유 현황 미제공"으로 둔다.

**2) 1라운드 (병렬)** — 같은 메시지에서 세 Agent를 동시에 스폰한다(`subagent_type`: `risk-aggressive`, `risk-conservative`, `risk-neutral`). 각 프롬프트에 넣는 것:
- 최종 결론 라벨 줄, 5.5 판정 근거 요약, 반박되지 않고 남은 가장 강한 반대 논거
- 실행 계획 기준선 출력 전체, 팩트시트, 보유 현황(없으면 "미제공")
- 01~05 보고서 경로(필요한 근거를 직접 읽게 한다)
- 지시: "기준선의 어느 숫자를 얼마로 바꿀지와 그 근거 데이터를 짝지어 제안하라. 새 웹 검색은 하지 않는다. 마지막 줄에 `**제안 실행 계획**:` 한 줄."

**3) 2라운드 (병렬, 1회)** — 각 Agent에 다른 두 성향의 1라운드 제안을 보내 한 번씩 반박·인정하게 하고, 최종 `**제안 실행 계획**:` 줄을 다시 받는다.

**4) Team Lead 결정 (Portfolio Manager 역할)** — 판정 규칙:
1. 세 제안은 항상 다르다. **차이 자체는 기준선을 그대로 두는 이유가 아니다.** 어느 쪽 근거가 데이터로 더 강한지 가려 숫자를 정한다.
2. 기준선에서 바꾼 숫자마다 이유(어느 성향의 어떤 데이터)를 한 줄로 쓴다. 바꾸지 않은 숫자는 "기준선 유지"와 이유.
3. 발언 순서·분량에 끌리지 않는다. 세 성향 중 하나를 그대로 채택해도 되지만 그 이유를 쓴다.
4. 토론에서 **판단(매수/관망/회피)이나 확신도를 바꿀 근거**가 나오면, 실행 계획만 고치지 말고 7단계로 돌아가 라벨 줄과 판정 근거를 고친 뒤 기준선을 다시 계산한다. 이유를 06 파일에 남긴다.
5. 비중 합계는 비중 상한을 넘지 않는다. 회피면 비중 상한 0%.

**5) 저장** — `reports/{회사명}/06-리스크토론-비중.md`:
- 기준선 출력 전체
- 1·2라운드 세 성향의 제안·반박 요약(성향별 최종 `**제안 실행 계획**` 줄 포함)
- Team Lead 결정: 기준선 대비 바뀐 숫자 표(항목 / 기준선 / 결정 / 이유) + 최종 `**실행 계획**:` 줄
- 최종보고서 7절에 같은 `**실행 계획**:` 줄을 넣는다(두 파일의 줄이 같아야 한다)

**폴백**: 리스크 Agent 정의가 로드되지 않으면 `general-purpose` 로 스폰하고 프롬프트에 성향을 명시한다. 병렬 실행이 안 되면 Team Lead가 세 성향을 순차로 작성하되, 06 파일에 "Team Lead 대리 작성"이라고 밝힌다.

`FAIL`(❌)이면 해당 파일을 고치고 다시 검사한다. 표본 검사 줄은 아래 표본 검사 결과를 적은 뒤에야 통과하므로, 표본 검사 후 한 번 더 실행해 `PASS`를 확인한다.

```bash
# Step 1 — 표본 검사 목록 추출 (15% 무작위 샘플링)
python3 tools/report_audit.py extract \
  --report <보고서 파일 경로>

# Step 2 — 목록의 각 항목을 신뢰할 수 있는 출처에서 재확인 (.claude/skills/financial-data/SKILL.md 참조)

# Step 3 — 출고/반려 판정 출력
python3 tools/report_audit.py verdict \
  --results '<채워진 JSON>' \
  --report <보고서 파일명>
```

**[출고]** 전부 통과 → 보고서 발행 가능; **[반려]** 미통과 항목 존재 → 수정 후 재심사.

## 중요 주의사항

0. **팩트시트 → 병렬 분석 → 교차 반론 → 판정 규칙 적용 → 종합 → 리스크 토론·실행 계획** 순서를 건너뛰지 않는다(1.6 / 4 / 5.5 / 7 / 7.5단계)
1. **4개 Agent는 반드시 병렬 실행** — 같은 메시지에서 Task 도구를 4번 호출
2. **Agent는 SendMessage로 보고** — 파일 협업이 아니라 메시지 통신이다
   - **폴백**: 팀 도구(TeamCreate/SendMessage)가 없는 환경이거나 병렬 Agent 실행이 실패(세션 한도 등)하면, team-lead가 4개 역할을 **순차 수행**하고 각 관점 보고서를 해당 파일에 직접 작성한다. 산출물 구조는 동일하게 유지한다
3. **데이터 정확성** — Agent가 WebSearch로 최신 데이터를 검색하고 핵심 데이터를 교차 검증하도록 요구
4. **결론은 명확하게** — 매수/관망/회피 제안과 구체적인 가격 구간 제시를 회피하지 않는다
5. **모든 분석에 데이터 근거** — 데이터 출처 첨부
6. **인내심 있게 대기** — 4개 Agent의 리서치에는 몇 분이 걸린다. 사용자에게 진행 상황을 실시간 갱신
7. **반편향 의식** — team-lead는 취합 시 반드시 평가한다: 각 Agent의 분석이 자료의 풍부함에 좌우되지는 않았는가? 시장 컨센서스에 과도하게 수렴하지는 않았는가? 최종 보고서에는 "정보 풍부도 등급"과 "AI 리서치 한계 고지"를 포함해야 한다
8. **정보 희소 시의 정직 원칙** — 추측으로 프레임워크를 채워 확실성을 가장하느니, 보고서에 여백을 남기고 "데이터 부족"을 표기하는 편이 낫다
